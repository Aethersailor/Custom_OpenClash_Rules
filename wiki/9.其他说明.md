## 1. 升级插件至 `dev` 版本

OpenClash 的 `dev` 版本通常包含最新的功能修复和改进。为简化从 `master` 版本升级到 `dev` 版本的流程，并方便系统重置后恢复环境，本项目提供自动化 Shell 脚本 `install_openclash_dev_update.sh`。

该脚本可以通过一条命令部署并更新 OpenClash 及其依赖环境。

### ✨ 脚本功能

脚本将按照以下顺序自动完成操作：

1. **环境检测：** 自动识别系统包管理器（`opkg` 或 `apk`）及防火墙架构（`iptables` 或 `nftables`），并安装缺失依赖。
2. **连接优化：** 按脚本逻辑更新必要的域名解析和 `hosts` 记录，以提高连接稳定性。
3. **下载优化：** 使用 jsDelivr CDN 或备用下载源，提高安装包下载成功率。
4. **智能配置：**
    - 自动检测 CPU 微架构并配置适配的 `core_version`。
    - 强制将内核更新分支设为 `dev`。
    - 自动根据剩余空间选择适配的 LightGBM 模型（Smart 内核模式下）。
5. **资源更新：** 同步更新 GeoIP、GeoSite、直连 IP 白名单等核心数据库及相关配置。
6. **配置恢复：** 支持加载 `/etc/config/openclash-set` 预设文件，用于保留自定义配置。
7. **服务启动：** 自动设置开机自启并启动服务。

### 📥 使用方法

> [!TIP]
> 推荐通过 SSH 连接设备，直接执行以下命令：

```bash
wget -qO- https://testingcf.jsdelivr.net/gh/Aethersailor/Custom_OpenClash_Rules@refs/heads/main/shell/install_openclash_dev_update.sh | sh
```

## 2. 关于个性化需求

本项目的 `Custom_Clash_Full.ini` 模板开放规则添加请求。

> [!WARNING]
> **注意：** 随着规则数量增加，模板体积可能会增大，从而影响解析性能。本项目不对规则过多产生的性能损耗承担责任。

若需要完全个性化的配置，建议采用以下方式：

### 🛠️ 推荐方案：使用 OpenClash 自定义规则

通过 OpenClash 的**「覆写设置」**功能添加自定义规则，操作最直接，并且不会破坏原有模板结构。

**操作路径：**
OpenClash →「覆写设置」→「规则设置」→「自定义规则」

勾选「自定义规则」，并按照标准 Clash 规则格式添加内容（需要去除 `#` 注释符）。

<img width="993" alt="custom_rules" src="https://github.com/user-attachments/assets/3b6e5ded-e624-4ffc-a77d-43ef0ad5931c" />

### 其他方案

- **Fork 后修改：** Fork 主仓库后，自行修改并维护模板文件。
- **规则附加：** 使用 OpenClash 的「规则附加」功能。

## 3. 关于小众域名收录

为优化分流体验，本项目持续收集被误分流的小众域名。

符合上游要求的域名会提交至 [felixonmars/dnsmasq-china-list](https://github.com/felixonmars/dnsmasq-china-list)，并由 [Loyalsoldier/v2ray-rules-dat](https://github.com/Loyalsoldier/v2ray-rules-dat) 合并到 GeoSite 数据库，实现不经内核的直连访问。

### ✅ 收录标准

提交的域名需满足以下条件：

1. **解析为 Fake-IP：** 域名经过 OpenClash 解析返回 Fake-IP。
2. **分流异常：** 未命中任何直连规则，被分流至「漏网之鱼」（Final）策略组。

建议同时满足以下条件：

1. **解析结果：** 域名解析为中国大陆 IP 地址。

### 📮 提交方式

### 💡 处理流程说明

> [!NOTE]
>
> 1. **提交说明：** 提交时请注明域名对应的网站名称，将优先收录至本项目的直连规则中。
> 2. **上游检测：** 维护者将校验域名是否符合上游收录标准（例如名称服务器（NS）、归属信息等）。
>     - **符合：** 提交 PR 至 GeoSite 上游。被收录后，OpenClash 将按直连逻辑处理，并绕过代理内核。
>     - **不符合：** 永久保留在本项目的直连规则中，由内核处理。
> 3. **规则清理：** 域名被 GeoSite 正式收录后，将从本项目的直连规则中移除。
