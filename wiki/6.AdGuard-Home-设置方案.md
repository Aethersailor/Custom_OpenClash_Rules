# AdGuard Home 图文设置方案

本文介绍如何在 ImmortalWrt / OpenWrt 主路由上，通过 LuCI 和 AdGuard Home 管理页面完成安装与配置。只有添加防火墙劫持规则时需要使用 SSH，命令可以整段复制粘贴。

本方案可以独立使用，也可以作为本项目 [OpenClash 设置方案](1.OpenClash-设置方案.md) 的可选广告过滤前端。AGH 的监听端口和前端劫持规则独立于 OpenClash，切换 OpenClash 的启停状态或本地 DNS 劫持模式时，无需重写这条规则。

**本方案支持随固件正常升级，无需重新设置。** 使用 owut / ASU 等方式保留配置及已安装软件包升级后，AGH 设置和防火墙劫持规则可继续使用，无需重新完成向导或部署规则。历史查询日志、统计数据的保留方式见第 9.3 节。

> [!IMPORTANT]
> 本文以使用 fw4 / nftables 的主路由为适用环境。安装前，路由器本来的 DNS 和上网功能应已正常；使用 OpenClash 时，请先完成主教程并确认其原有配置正常。
>
> 截图来自实际安装过程，测试机地址为 `192.168.1.21`。文中「路由器 IP」均应替换为自己的 LAN 地址，例如 `192.168.1.1`。不要把截图中的测试地址直接填进自己的网络配置。

## 1. 实现效果和 DNS 请求流程

配置完成后，经过主路由的 LAN 设备普通 DNS 查询，无论发送到路由器还是手工指定的公网 DNS，只要使用 **UDP/TCP 53 端口**，都会先交给 AGH。

```text
LAN 设备
  │  UDP/TCP 53：目标可以是路由器，也可以是公网 DNS
  ▼
独立 fw4 劫持规则（优先级 -151）
  ▼
AGH :5353
  ├─ 命中过滤规则 → 直接返回拦截结果
  ├─ 命中缓存     → 返回缓存结果
  └─ 需要上游解析 → 127.0.0.1:53（dnsmasq）
                       ├─ OpenClash 未安装或已关闭 → 原有默认上游 DNS
                       └─ OpenClash 已启用
                            → OpenClash DNS（通常为 :7874）
                            → 按原有配置使用运营商 DNS、DoH 或 SmartDNS 等上游
```

关键点：

- **AGH 在 dnsmasq 前面**，能够记录下游设备的真实来源 IP，而不是只看到路由器。
- **dnsmasq 继续监听 53**，保留原有 DHCP、本地域名与 OpenClash 集成方式。
- **AGH 监听 5353**，不会抢占 dnsmasq 的 53。
- 使用 OpenClash 时，继续遵循主教程的「使用 Dnsmasq 转发」。若改用 OpenClash 的「使用防火墙转发」，本机发往 53 的上游查询可能由 OC 再转入其 DNS；LAN 查询仍先经过 AGH。
- 这条规则只处理从指定 LAN 设备进入路由器的普通 DNS。路由器本机发起的查询、DoH、DoT、DoQ 以及不经过该路由器的流量，不属于它的接管范围。查询 AAAA 记录和使用 IPv6 传输 DNS 是两件事。

> [!NOTE]
> 这里的「不依赖 OpenClash」指前端劫持与 AGH 服务可以独立工作。OpenClash 关闭后，依赖代理的网站不会因此自动具备直连能力；dnsmasq 原有默认上游也应可用。

## 2. 安装软件包

### 2.1 更新软件包列表

进入 LuCI「系统 → 软件包」，点击「更新列表」，等待更新完成后关闭结果窗口。

在筛选框输入：

```text
adguardhome
```

![在 LuCI 软件包页面筛选 adguardhome](https://raw.githubusercontent.com/wiki/Aethersailor/Custom_OpenClash_Rules/images/adguardhome/01-install-packages.png)

### 2.2 安装 LuCI 插件

如果列表中有简体中文语言包 **`luci-i18n-adguardhome-zh-cn`**，直接点击该包的「安装」。LuCI 插件 `luci-app-adguardhome` 和 AGH 本体 `adguardhome` 会作为依赖自动安装，无需逐个安装。

如果没有该语言包，则直接安装 **`luci-app-adguardhome`**，AGH 本体 `adguardhome` 同样会作为依赖自动安装。确认安装窗口中应包含这些尚未安装的依赖。

本文演示使用 **ImmortalWrt Snapshot**，演示时的软件源未提供对应的中文语言包，因此截图中直接安装 `luci-app-adguardhome`。

![确认安装 LuCI 插件及 AGH 本体](https://raw.githubusercontent.com/wiki/Aethersailor/Custom_OpenClash_Rules/images/adguardhome/02-install-confirm.png)

不同固件的翻译完整度不同，截图中部分选项仍为英文。

安装完成后刷新 LuCI 页面，进入「服务 → AdGuard Home」。菜单尚未出现时，退出 LuCI 后重新登录。

## 3. 设置 LuCI 服务选项

在「服务 → AdGuard Home」中：

| 选项 | 建议设置 |
| --- | --- |
| 启用 | 勾选 |
| Configuration file / 配置文件 | `/etc/adguardhome/adguardhome.yaml` |
| Working directory / 工作目录 | `/etc/adguardhome/work` |
| Service user / 服务用户 | 保持 `adguardhome` |
| Service group / 服务组 | 保持 `adguardhome` |
| Verbose logging / 详细日志 | 不勾选 |
| 高级设置 | 初次部署保持默认 |

点击「保存并应用」，等待服务显示「运行中」。

![LuCI 中的 AGH 服务与工作目录设置](https://raw.githubusercontent.com/wiki/Aethersailor/Custom_OpenClash_Rules/images/adguardhome/03-luci-service.png)

工作目录保存过滤列表、查询日志和统计数据。OpenWrt 的默认 `/var` 通常位于内存文件系统中；这里使用持久存储上的目录，以免运行数据因重启丢失。设备应有足够可写空间；安装包下载大小不代表安装后和运行时的总空间需求。

**首次安装时，配置文件路径存在于页面中，但实际 YAML 文件尚未生成，是正常现象。** 继续完成下一节的网页向导，不需要手工创建配置文件。

## 4. 完成 AGH 安装向导

### 4.1 打开向导

在浏览器访问：

```text
http://路由器IP:3000
```

例如，本文测试机使用 `http://192.168.1.21:3000`。选择「简体中文」，点击「开始配置」。

![AGH 安装向导首页](https://raw.githubusercontent.com/wiki/Aethersailor/Custom_OpenClash_Rules/images/adguardhome/04-wizard-start.png)

### 4.2 设置网页管理端口和 DNS 监听端口

按照下表设置：

| 项目 | 设置 |
| --- | --- |
| 网页管理界面：监听接口 | 选择 LAN 对应接口，例如 `br-lan` |
| 网页管理界面：端口 | 本文使用 `3001` |
| DNS 服务器：监听接口 | 所有接口 |
| DNS 服务器：端口 | `5353` |

![设置 LAN 管理地址、3001 管理端口和 5353 DNS 端口](https://raw.githubusercontent.com/wiki/Aethersailor/Custom_OpenClash_Rules/images/adguardhome/05-wizard-listen.png)

向导本身使用 `3000`。如果该版本允许管理界面继续使用 `3000`，可以沿用；本文在最终提交时遇到了「address already in use」，因此改为 `3001`。完成向导后，应使用最后填写的管理端口访问。

DNS 端口不要填写 `53`，也不要选择只监听 `lo / 127.0.0.1`。前者会与 dnsmasq 冲突，后者无法接收从 LAN 重定向而来的请求。

`5353` 也可能被 mDNS / Avahi 等服务占用。如果向导提示冲突，应先核对占用服务；若自行选择其他空闲端口，后面的防火墙重定向目标也必须同步修改。DNS 选择「所有接口」时，继续保持 WAN 入站防护，不向公网开放 DNS 和管理端口。

### 4.3 创建后台账号

本文演示使用：

| 项目 | 演示值 |
| --- | --- |
| 用户名 | `root` |
| 密码 | `password` |
| 确认密码 | `password` |

当前演示版本要求密码为 8～72 个字符，`root` 只有 4 个字符，无法通过向导。

![创建 AGH 后台演示账号](https://raw.githubusercontent.com/wiki/Aethersailor/Custom_OpenClash_Rules/images/adguardhome/06-wizard-account.png)

> [!WARNING]
> `root / password` 仅为本文演示账号，实际部署请设置独立强密码。AGH 后台账号与 LuCI / SSH 系统账号是不同的账号；无需把服务运行用户改成 root。

### 4.4 完成向导并登录

在「配置您的设备」页面继续点击「下一步」，然后点击「打开仪表盘」。

本文采用防火墙接管 53 端口的方式，客户端仍按正常方式使用 DNS，无需在 DHCP 中填写 `5353`，也无需启用 AGH 的 DHCP 服务。

用刚才设置的账号登录：

```text
http://路由器IP:3001
```

![使用演示账号登录 AGH](https://raw.githubusercontent.com/wiki/Aethersailor/Custom_OpenClash_Rules/images/adguardhome/07-login.png)

## 5. 设置上游 DNS

进入 AGH「设置 → DNS 设置」。

### 5.1 上游、后备和本地反向解析

| 选项 | 建议设置 |
| --- | --- |
| 上游 DNS 服务器 | 删除默认地址，只填写 `127.0.0.1:53` |
| 上游模式 | 负载均衡 |
| 后备 DNS 服务器 | 留空 |
| Bootstrap DNS 服务器 | `127.0.0.1:53` |
| 私人反向 DNS 服务器 | 可填写 `127.0.0.1:53`，明确交由本机 dnsmasq 处理 |
| 使用私人反向 DNS 解析器 | 勾选 |
| 启用客户端 IP 地址的反向解析 | 勾选 |
| 上游超时 | 保持默认 `10` 秒 |

参考主路由的私人反向 DNS 字段为空，会使用系统检测到的本机解析器；本文显式填写同一个 dnsmasq 地址，便于新手确认请求去向。

点击「测试上游」，显示服务器正常后，点击本节底部的「应用」。

![AGH 的上游和私人反向 DNS 配置](https://raw.githubusercontent.com/wiki/Aethersailor/Custom_OpenClash_Rules/images/adguardhome/08-dns-upstream.png)

Bootstrap 用于解析上游服务器的域名。本文上游已经是数字 IP，不依赖它完成寻址；这里保留本机地址即可。

**保留 dnsmasq 自己原来的上游，不要将 dnsmasq 的 DNS 转发地址改为 AGH 的 `127.0.0.1:5353`。** 否则会形成「AGH → dnsmasq → AGH」的循环。

使用 OpenClash 时，本机 dnsmasq 如何转入 OC，仍由 OpenClash 管理；使用 SmartDNS 时，也继续沿用主教程中 OC 与 SmartDNS 的对接关系。

### 5.2 DNS 服务配置

| 选项 | 建议设置 |
| --- | --- |
| 速度限制 | `0`，不限制可信 LAN 客户端的查询速率 |
| EDNS 客户端子网 | 不勾选 |
| 启用 DNSSEC | 勾选 |
| 禁用 IPv6 地址的解析 | 不勾选 |
| 拦截模式 | 默认 |
| 屏蔽的 TTL 应答 | `0` |

点击该区域的「保存」。

![DNS 服务配置与 TTL 设置](https://raw.githubusercontent.com/wiki/Aethersailor/Custom_OpenClash_Rules/images/adguardhome/09-dns-service.png)

DNSSEC 的效果取决于上游解析链是否支持相关信息。AGH 不主动丢弃 AAAA 查询，不代表上游一定返回 IPv6 地址；OpenClash 和上游解析器的 IPv6 设置仍会影响最终结果。

## 6. 设置缓存，并理解 Fake-IP 的取舍

### 6.1 AGH 缓存

在同一页面的「DNS 缓存配置」中设置：

| 选项 | 建议设置 |
| --- | --- |
| 启用缓存 | 勾选 |
| 缓存大小 | 保持默认，本文版本为 `4194304` 字节，即 4 MiB |
| 覆盖最小 TTL 值 | `0` |
| 覆盖最大 TTL 值 | `0` |
| 乐观缓存 | 建议勾选；配合 OC Fake-IP 时先阅读下一节 |

点击本区域的「保存」。

![默认缓存大小、零 TTL 改写与乐观缓存](https://raw.githubusercontent.com/wiki/Aethersailor/Custom_OpenClash_Rules/images/adguardhome/10-dns-cache.png)

两个「覆盖 TTL」设为 `0`，表示关闭本地 TTL 改写，遵循上游返回的 TTL。**这不会把所有 DNS 响应的 TTL 设为 0，也不会关闭缓存。** 「屏蔽的 TTL 应答」则控制拦截结果在客户端的缓存时间，含义不同。

乐观缓存会在条目过期后先返回旧结果，并尝试刷新。它可减少等待，但旧结果也可能与上游当前状态不同；它不等同于始终返回最新解析结果。

### 6.2 使用 OpenClash Fake-IP 时的配套设置

**在 OpenClash 的 Fake-IP 模式下开启 AGH 乐观缓存，本教程要求同时开启 OC 的「Fake-IP 持久化」。** 不使用 OC，或不使用 Fake-IP 模式时，不需要设置这一项。

进入 LuCI「服务 → OpenClash → 覆写设置 → DNS 设置」，勾选「Fake-IP 持久化」，点击「保存配置」，再「应用配置」使设置生效。

![OpenClash 的 Fake-IP 持久化选项](https://raw.githubusercontent.com/wiki/Aethersailor/Custom_OpenClash_Rules/images/adguardhome/18-openclash-fake-ip.png)

原因是 AGH 可能在过期缓存中保留 Fake-IP，而 OC 重启后如果丢失对应的域名映射，旧地址可能无法继续正确使用。持久化有助于让映射在内核重启后延续。

持久化需要写入映射文件。**首次分配新 Fake-IP 时可能增加解析耗时，慢速存储上的影响更明显；已经建立的映射和每次查询的开销不相同。** 它不是无代价的性能优化，请根据设备和使用需求取舍。

| 选择 | 配置方式 |
| --- | --- |
| 使用乐观缓存，接受持久化开销 | 开启 AGH 乐观缓存，同时开启 OC Fake-IP 持久化 |
| 不希望为乐观缓存承担持久化开销 | 关闭 AGH 乐观缓存，普通缓存保持默认；OC 持久化按自身需求决定 |

关闭乐观缓存并不等于所有缓存一致性问题都自动消失。切换 Fake-IP / Redir-Host、关闭 OC，或清理 OC 的 Fake-IP 持久化数据后，如果仍有旧地址导致访问异常，应在 AGH「DNS 设置」点击「清除缓存」，并刷新终端或浏览器缓存。

持久化解决的是映射延续问题，不能让 OC 关闭后继续处理 Fake-IP 流量。**前端劫持规则保持工作，与缓存中的旧结果是否适用于当前模式，是两个独立问题。**

### 6.3 保持与本项目主教程一致

OpenClash 已按主教程配置好的用户，继续使用「插件设置 → DNS 设置 → 使用 Dnsmasq 转发」，无需改动 OC 的 DNS 监听端口。

![保持主教程的 Dnsmasq 转发模式](https://raw.githubusercontent.com/wiki/Aethersailor/Custom_OpenClash_Rules/images/adguardhome/20-openclash-dns-mode.png)

本方案在 AGH 前面增加独立劫持入口，不替换主教程的节点、订阅、分流规则和上游 DNS 设置。DNS 广告过滤是可选功能，并不保证降低所有网站的总访问延迟。

## 7. 设置查询日志和统计数据

进入 AGH「设置 → 常规设置」。

### 7.1 过滤器和附加服务

- 保持「使用过滤器和 Hosts 文件以拦截指定域名」启用。
- 参考主路由，过滤器更新间隔设为「1 小时」；低频更新需求也可以按实际情况选择更长间隔。
- 「浏览安全」「家长控制」「安全搜索」按需求开启。本文参考配置均未启用这些附加功能。

![常规设置中的过滤器更新与附加功能](https://raw.githubusercontent.com/wiki/Aethersailor/Custom_OpenClash_Rules/images/adguardhome/13-general-settings.png)

### 7.2 查询日志保留 6 小时

- 勾选「启用日志」。
- 为保留完整设备 IP，不勾选「匿名化客户端 IP」。
- 查询日志保留时间选择「6 小时」。
- 点击本区域的「保存」。首次从较长保留时间缩短时，确认提示中的历史数据清理。

![查询日志保留 6 小时](https://raw.githubusercontent.com/wiki/Aethersailor/Custom_OpenClash_Rules/images/adguardhome/11-query-log.png)

查询日志逐条记录 DNS 请求，是更值得控制的存储占用来源。6 小时通常足够排查近期问题，需要追踪更早记录时再按需延长；实际空间还与查询量和日志轮转有关。

### 7.3 统计保留时间按需选择

保持「启用统计数据」勾选，统计保留时间按需求选择，然后点击本区域的「保存」。本文截图使用与主路由一致的「90 天」，并非必选值。

![统计保留时间按需选择，示例为 90 天](https://raw.githubusercontent.com/wiki/Aethersailor/Custom_OpenClash_Rules/images/adguardhome/12-statistics.png)

统计保存的是汇总数据，与逐条查询日志相比通常占用较小，保留时间对总空间的影响相对有限，可以根据需要选择。这不表示统计数据永远不占空间或完全不随保留时间增长。

## 8. 添加适合简体中文环境的过滤列表

进入「过滤器 → DNS 黑名单」，点击「添加黑名单」，再选「从列表中选择」。

![从 AGH 内置目录选择过滤列表](https://raw.githubusercontent.com/wiki/Aethersailor/Custom_OpenClash_Rules/images/adguardhome/14-filter-source.png)

本文建议先启用以下三份 DNS 列表：

| 列表 | 用途 |
| --- | --- |
| AdGuard DNS filter | 通用广告和跟踪域名过滤，通常已默认添加 |
| AWAvenue Ads Rule | 补充简体中文应用和网站常见广告域名 |
| CHN: AdRules DNS List | 补充中文地区的 DNS 广告过滤 |

![在内置目录中选择 AWAvenue Ads Rule](https://raw.githubusercontent.com/wiki/Aethersailor/Custom_OpenClash_Rules/images/adguardhome/15-filter-awavenue.png)

![在区域列表中选择 CHN: AdRules DNS List](https://raw.githubusercontent.com/wiki/Aethersailor/Custom_OpenClash_Rules/images/adguardhome/16-filter-adrules.png)

从内置目录勾选并「保存」即可，不必再以自定义 URL 重复添加。已存在的 AdGuard DNS filter 保持启用，其他默认未启用的列表可以保持原状。

返回黑名单页面，点击「检查更新」，确认启用的列表已经下载，规则数不再为 `0`。

![三份推荐列表已启用并成功下载](https://raw.githubusercontent.com/wiki/Aethersailor/Custom_OpenClash_Rules/images/adguardhome/17-filter-lists.png)

不要全选目录中的列表。列表存在重叠，也可能误拦正常服务；数量和规则条数不等于实际效果。低内存设备可以先使用 AdGuard DNS filter 与 AWAvenue，再根据需要增加 AdRules。

遇到应用异常时，先在查询日志找到对应设备、域名和命中列表，再按实际情况添加允许规则。不要仅凭「网站打不开」就认定是 AGH，也不要直接放行整个大型域名后缀来掩盖问题。

## 9. 添加独立防火墙劫持规则

### 9.1 为什么需要单独加这条规则

客户端通常向 53 端口发送普通 DNS 查询。AGH 监听 `5353`，因此需要由防火墙把经过主路由的 LAN TCP/UDP 53 查询转给 AGH。

规则使用独立的 `agh_dns_front` 链，优先级 `-151`，先于常规 mangle `-150` 处理。它不依赖 OC 的自定义防火墙脚本入口，也不会覆盖用户已有的 OC 脚本。

### 9.2 通过 SSH 复制粘贴部署

使用 SSH 登录路由器。**这里使用的是路由器系统账号及其实际密码或密钥，不是 AGH 的后台账号。**

以下命令会自动识别名为 `lan` 的逻辑接口所使用的设备，并把 TCP/UDP 53 转到 `5353`。适用于本文的标准 LAN 配置；自行重命名逻辑接口或使用多个 LAN / 访客网络时，需要按实际网络调整。

整段复制到路由器 SSH 终端执行：

```sh
LAN_DEV="$(ubus call network.interface.lan status | jsonfilter -e '@.l3_device')"
if [ -z "$LAN_DEV" ]; then
    echo "无法识别 LAN 设备，请先检查 LAN 接口。"
    exit 1
fi
RULE_FILE=/etc/nftables.d/90-adguardhome-dns.nft
BACKUP_FILE="/root/90-adguardhome-dns-$(date +%Y%m%d-%H%M%S).bak"
mkdir -p /etc/nftables.d
HAD_RULE=0
if [ -f "$RULE_FILE" ]; then
    cp -p "$RULE_FILE" "$BACKUP_FILE" || exit 1
    HAD_RULE=1
fi
cat > "$RULE_FILE" <<EOF
chain agh_dns_front {
    type nat hook prerouting priority -151; policy accept;
    iifname "$LAN_DEV" meta l4proto { tcp, udp } th dport 53 counter redirect to :5353 comment "AdGuard Home DNS front"
}
EOF
if fw4 check && /etc/init.d/firewall reload; then
    nft list chain inet fw4 agh_dns_front
    echo "已接管 LAN 的 TCP/UDP 53，转发至 AGH 5353。"
else
    if [ "$HAD_RULE" = 1 ]; then
        cp -p "$BACKUP_FILE" "$RULE_FILE"
    else
        rm -f "$RULE_FILE"
    fi
    fw4 check && /etc/init.d/firewall reload
    echo "加载失败，已恢复部署前的规则文件。"
    exit 1
fi
```

出现「Ruleset passes nftables check」及「已接管 LAN 的 TCP/UDP 53」后，查看输出中的 `redirect to :5353`。优先级有时显示为 `mangle - 1`，等同于 `-151`。

如果检查失败，命令会恢复部署前的规则文件。修改前已有同名文件时，原文件备份位于输出所对应时间的 `/root/90-adguardhome-dns-时间.bak`。

默认 LAN 入站策略为「接受」时可以直接使用。若已限制 LAN 访问路由器，还需通过 LuCI「网络 → 防火墙 → 通信规则」允许 LAN 到路由器本机的 TCP/UDP `5353`；不要添加 WAN 放行。

### 9.3 重启和保留配置升级

该文件由 fw4 自动加载，正常启动防火墙后会再次生效。

ImmortalWrt 的 firewall4 已默认保留 `/etc/nftables.d/`，正常「保留配置」升级时，无需为这份规则再手工添加保留项。AGH 软件包也声明保留其默认 YAML 配置文件。可以在 LuCI「系统 → 备份与更新」查看生成备份的文件清单，核对实际路径。

本文自定义工作目录包含可重新下载的过滤缓存，以及查询日志、统计数据。如果希望这些运行数据也跨固件升级保留，可在「备份与更新 → 配置」追加 `/etc/adguardhome/work/`；保留它会增加备份体积。仅保留 YAML 时，历史运行数据可能丢失，列表可按配置重新下载。

## 10. 验证劫持、设备记录和广告拦截

### 10.1 在 LAN 客户端发起 UDP 和 TCP 查询

下面是 Windows 客户端的示例。命令应在经过这台主路由的下游设备上执行：

```bat
nslookup www.qq.com 223.5.5.5
nslookup -vc www.qq.com 223.5.5.5
```

第一条通常通过 UDP 查询；第二条强制使用 TCP。虽然手工指定了公网 DNS，只要流量经过本文主路由，仍应先进入 AGH。

在 AGH「查询日志」中搜索客户端 IP 或 `www.qq.com`，确认看到真实客户端 IP。

![查询日志中的实际客户端和本机过滤命中](https://raw.githubusercontent.com/wiki/Aethersailor/Custom_OpenClash_Rules/images/adguardhome/19-query-proof.png)

> [!IMPORTANT]
> 单纯「能解析」不能证明劫持成功。应同时确认 AGH 查询日志出现了该设备的请求，并检查防火墙规则计数增加。
>
> 在主路由本机执行同样的查询，不等同于 LAN 客户端测试，因为本文规则只匹配从 LAN 设备进入的流量。

需要核对防火墙计数时，在路由器 SSH 终端执行：

```sh
nft list chain inet fw4 agh_dns_front
```

计数统计的是匹配到的新连接首包，并不一定与 AGH 的查询条数一一对应。

### 10.2 验证广告域名确实被本机拦截

在客户端查询一个由当前列表拦截的域名，例如：

```bat
nslookup pagead2.googlesyndication.com 223.5.5.5
```

默认拦截模式下，可能看到 `0.0.0.0`。同时在 AGH 日志确认显示「已拦截」和具体命中的本机过滤列表。

过滤列表会更新，域名是否命中应以当时的日志为准；单看返回零地址不足以排除上游过滤的影响。

### 10.3 检查 OC 启停和防火墙重建

使用 OC 的用户，可以依次检查：

1. OC 运行时，客户端查询仍出现在 AGH。
2. 在 LuCI 关闭 OC 后，AGH 仍可过滤广告，普通解析由 dnsmasq 的默认上游继续处理。
3. 重新启用 OC 后，再次查询并确认记录。
4. 在 LuCI 重载防火墙，等待 OC 完成规则重建，再重复测试。

切换期间若受到旧 Fake-IP 缓存影响，按照第 6 节清理 AGH 和客户端缓存。

演示验证覆盖了本机 OC 关闭、Dnsmasq 转发和防火墙转发状态下的 UDP/TCP DNS 请求。代理节点本身、运营商网络以及外部上游的可用性，仍应按主教程分别验证。

## 11. 常见问题与撤销方法

### 配置文件为空或不存在

首次运行、尚未完成网页向导时可能如此。先确认 LuCI 服务已启动，再访问 `http://路由器IP:3000` 完成向导。

### 完成向导后原来的 3000 页面打不开

管理端口已经改为 `3001`，请访问新的地址。若选择了 LAN 管理接口，也应通过对应的 LAN 地址访问。

### 查询日志只有路由器 IP

检查是否误把 dnsmasq 的上游指向 AGH，导致链路变成「客户端 → dnsmasq → AGH」。本文通过独立前端劫持接收客户端请求，AGH 的上游应为本机 dnsmasq。

### 查询没有进入 AGH

检查客户端流量是否经过这台主路由、规则匹配的 LAN 设备是否正确、AGH 是否监听 `5353`、客户端是否正在使用加密 DNS，以及 LAN 入站策略是否允许本机端口。

### OC 关闭后部分网站仍得到旧的 Fake-IP

这是缓存状态需要同步的问题，不能据此认定前端规则被删除。清理 AGH、客户端及浏览器缓存后再测试；如果 dnsmasq 本来的默认上游已经不可用，应先修复该上游。

### 撤销本文新建的劫持规则

在 SSH 中把规则文件移出自动加载目录，再检查并重载防火墙：

```sh
mv /etc/nftables.d/90-adguardhome-dns.nft \
    "/root/90-adguardhome-dns-$(date +%Y%m%d-%H%M%S).disabled"
fw4 check && /etc/init.d/firewall reload
```

如果部署前已有自己的同名规则，应恢复之前的备份。撤销劫持不会自动卸载 AGH，也不会删除过滤列表和日志。
